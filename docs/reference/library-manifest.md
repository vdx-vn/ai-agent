# Library Manifest

| Skill | Class | Category | Primary artifact | Key tie-breaker | Compose with |
|---|---|---|---|---|---|
| `odoo-think` | task | Sprint task skills | Risk-oriented scoping brief with module map, business entrypoint, cross-app impact, and open questions. | Use this skill only when the primary requested output is a scoping brief or impact diagnosis. If the user wants ordered steps, file-by-file actions, or acceptance criteria, hand off to `odoo-plan`. | `odoo-plan`, `odoo-architecture` |
| `odoo-plan` | task | Sprint task skills | Ordered execution plan with file map, acceptance criteria, test matrix, rollout notes, and open decisions. | Use this skill only when the user wants a plan artifact. If the user wants a risk brief, use `odoo-think`. If the user wants code edits, use `odoo-build`. | `odoo-think`, `odoo-test`, `odoo-upgrade-migration` |
| `odoo-build` | task | Sprint task skills | Concrete in-scope code or configuration changes plus noted assumptions and follow-up validation needs. | Use this skill only when the primary requested output is changed code or config artifacts. If the user is still deciding approach, use `odoo-plan`. | `odoo-orm-modeling`, `odoo-view-ui`, `odoo-security`, `odoo-upgrade-migration` |
| `odoo-review` | task | Sprint task skills | Structured findings on an existing diff or artifact, separated into required fixes, open risks, and optional improvements. | Use this skill only when the primary requested output is review findings on an existing artifact. If the user wants executed validation evidence, use `odoo-test`. If the prompt centers on exposure or trust boundaries, compose with or defer to `odoo-security`. | `odoo-security`, `odoo-test`, `odoo-testing-reference` |
| `odoo-test` | task | Sprint task skills | Current-change validation evidence or validation plan tied to a specific diff, addon, bug, or runtime scenario. | Use this skill only when the primary requested output is validation for a concrete change now. If the user asks which Odoo test framework or tags to use in general, hand off to `odoo-testing-reference`. If the user wants findings on an existing artifact without validation execution, use `odoo-review`. | `odoo-review`, `odoo-testing-reference`, `odoo-performance` |
| `odoo-ship` | task | Sprint task skills | Go or no-go rollout checklist with staging verification, release sequencing, rollback cautions, and production notes. | Use this skill only when the user wants release readiness or rollout sequencing. If the user needs CLI flag semantics or environment mechanics, hand off to `odoo-delivery-ops`. If the primary issue is data or schema evolution, compose with `odoo-upgrade-migration`. | `odoo-delivery-ops`, `odoo-upgrade-migration`, `odoo-test` |
| `odoo-reflect` | task | Sprint task skills | Retrospective with lessons, remaining gaps, and concrete follow-up actions. | Use this skill only when the primary requested output is a retrospective or lessons learned artifact after work already happened. | `odoo-review`, `odoo-test` |
| `odoo-architecture` | reference | Technical reference skills | Architecture recommendation with target addon, dependency rationale, and bridge-module guidance. | Use this skill only when the primary requested output is an addon-placement or dependency decision. | `odoo-plan`, `odoo-build`, `odoo-orm-modeling` |
| `odoo-orm-modeling` | reference | Technical reference skills | ORM modeling guidance with field or method recommendations and anti-pattern checks. | Use this skill only when the primary requested output is a model or ORM design decision. | `odoo-build`, `odoo-performance`, `odoo-security` |
| `odoo-view-ui` | reference | Technical reference skills | UI guidance with view strategy, inheritance notes, and action or menu recommendations. | Use this skill only when the primary requested output is a view, action, menu, template, xpath, OWL, or client-side UI decision. Even on website pages, keep this skill primary when the user asks about template or UI mechanics. | `odoo-build`, `odoo-architecture` |
| `odoo-security` | reference | Technical reference skills | Security assessment with trust boundaries, permission checks, exposure risks, and required safeguards. | Use this skill only when the primary requested output is a trust-boundary or exposure assessment. If the user wants a broad code review, use `odoo-review` and compose with this skill only when security is central. | `odoo-review`, `odoo-build`, `odoo-test` |
| `odoo-testing-reference` | reference | Technical reference skills | Framework and test-authoring guidance for future or current test design, without claiming current-change readiness. | Use this skill only when the primary requested output is framework or test-authoring guidance. If the user asks whether current work is tested or safe, use `odoo-test`. | `odoo-test`, `odoo-performance`, `odoo-view-ui` |
| `odoo-performance` | reference | Technical reference skills | Performance guidance with hotspot hypotheses, optimization levers, and validation ideas. | Use this skill only when the primary requested output is performance diagnosis or optimization guidance. | `odoo-test`, `odoo-orm-modeling`, `odoo-review` |
| `odoo-integration-api` | reference | Technical reference skills | Integration design guidance with auth model, data flow, safety considerations, and operational constraints. | Use this skill only when the primary requested output is an external integration design or RPC or API decision. | `odoo-security`, `odoo-delivery-ops`, `odoo-build` |
| `odoo-upgrade-migration` | reference | Technical reference skills | Migration strategy with data-preservation plan, script notes, rollout order, and validation needs. | Use this skill only when the primary requested output is migration or upgrade strategy. If the user mainly wants command semantics, use `odoo-delivery-ops`. | `odoo-ship`, `odoo-plan`, `odoo-delivery-ops`, `odoo-build` |
| `odoo-delivery-ops` | reference | Technical reference skills | Operational mechanics guidance covering commands, flags, environment behavior, and runtime cautions. | Use this skill only when the primary requested output is command, flag, worker, or environment semantics. If the user asks whether a release is ready, use `odoo-ship`. | `odoo-ship`, `odoo-test`, `odoo-upgrade-migration` |
| `pylint-code-review` | reference | Technical reference skills | Structured Python static-analysis review findings with pylint rule names, grouped issues, and fix guidance. | Use this skill only when the primary requested output is Python lint or static-analysis review findings. If the user wants non-Python review, runtime validation, or direct code changes, another workflow should own the request. | `odoo-build`, `odoo-test` |
| `cavecrew` | utility | Token utility skills | Decision guide for compressed subagent delegation with investigator, builder, and reviewer presets. | Use this only when the user asks to delegate, use cavecrew, spawn compressed subagents, or save context during subagent work. | none |
| `caveman` | utility | Token utility skills | Ultra-compressed communication mode for token-efficient technical responses. | Use this only when the user asks for caveman mode, less tokens, brief output, or `/caveman`. | none |
| `caveman-commit` | utility | Token utility skills | Compressed conventional commit message generator. | Use this only when the user asks for a compact commit message. | none |
| `caveman-compress` | utility | Token utility skills | Compressor for natural-language memory files while preserving technical substance. | Use this only when the user asks to compress memory files or persistent instructions. | none |
| `caveman-help` | utility | Token utility skills | Quick-reference card for caveman modes, skills, and commands. | Use this only for `/caveman-help`, caveman help, or equivalent help requests. | none |
| `caveman-review` | utility | Token utility skills | Compressed one-line code review comment formatter. | Use this only when the user asks for compressed review comments. | none |
| `caveman-stats` | utility | Token utility skills | Token usage and estimated savings reporter for caveman sessions. | Use this only when the user asks for caveman stats or token savings. | none |
